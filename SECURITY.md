# Security policy

## Reporting a vulnerability

Report suspected vulnerabilities through GitHub Private Vulnerability
Reporting on the public repository:
<https://github.com/MicheleDataBeat/super-hero-lite/security/advisories/new>.
**Do not report vulnerabilities in public Issues.**

Private Vulnerability Reporting is enabled on the public repository. Keeping
it enabled is a release prerequisite; it is a repository setting the
maintainers manage according to GitHub's official [private vulnerability
reporting guidance](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting),
not an action taken by a release or an ordinary pull request. See the
[release model](docs/release-model.md).

Do not include credentials, tokens, private keys, or unnecessary personal data
in any report. Provide a minimal reproduction and enough impact detail for
maintainers to assess the report without widening exposure.

## Other channels

- Product questions and non-security help belong in [Support](SUPPORT.md).
- Conduct concerns belong in the [Code of Conduct](CODE_OF_CONDUCT.md)
  reporting channel.
- Project decisions and ordinary defects belong in [Governance](GOVERNANCE.md)
  and the contribution process in [Contributing](CONTRIBUTING.md).
