# Governance

## Stewardship

MicheleDataBeat is the project steward and makes release, maintenance and
roadmap decisions. The aim is a small, legible governance core with
host-specific behavior held at an explicit seam, and no more machinery than
the risks it protects against justify.

## How decisions are made

A material behavior, compatibility or governance change begins with an Issue in
this repository, then receives maintainer review. Review considers user
impact, reversibility, security, documentation, tests, and whether the change
is the smallest one that achieves the outcome.

Ordinary pull requests do not publish a repository or a release. Public
distribution is a separate, explicitly gated process described in the
[release model](docs/release-model.md).

## Public intake

Publication added the community intake this repository intentionally withheld
while private: a [Code of Conduct](CODE_OF_CONDUCT.md) with a real private
reporting address, and issue forms pointing at the channels below. Announcing
a channel that does not exist would have been worse than having none, so these
were prerequisites of the first public release rather than files copied from
an ancestor ahead of need. See the [release model](docs/release-model.md).

## Channel boundaries

- Security vulnerabilities: [Security](SECURITY.md).
- Support and usage questions: [Support](SUPPORT.md).
- Conduct reports: the private address in the [Code of Conduct](CODE_OF_CONDUCT.md).
- Product, behavior and architecture decisions: this document and
  [Contributing](CONTRIBUTING.md).
